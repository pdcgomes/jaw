# jaw 0.1.1: publishing it

`v0.1.1` tagged and released with its source tarball and Jaw.app's zip, and the tap's formula moved to 0.1.1. Every step is the coordinator's, as the owner chose on 7 November, while he's away until 21 November. Jaw.app goes out signed with his Developer ID but not notarized, as he answered at 09:32 that day: Cursor's sandbox can't reach Apple's notary service, and the notes say how to open it. Notarizing the same zip later, step 10, is his and optional, and replaces the release's file without a new release. 0.1.0's checklist made the repository public and the tap `pdcgomes/homebrew-jaw`, and did the terms and side-project check, so none of those is here. Each step has its commands, what to see, and what undoes it if it fails. About an hour, most of it the tarball's and Jaw.app's builds.

The tag, the tarball and Jaw.app's zip are made first, on this Mac alone, so one that doesn't build leaves nothing public. This Mac is the owner's, and his own Jaw and jawd run on it: nothing in these steps installs, opens or stops a jaw.

## 3. Tag v0.1.1, on this Mac only


## 5. Jaw.app, built, signed and zipped

```sh
cd ~/src/jaw-v0.1.1 && mise run mac
```

- See: `==> the build Mac doesn't answer; building here`, as it's packed away; then `==> mac/build/release/Jaw.app (…), jawd 0.1.1, built from v0.1.1`. `mise run mac` (`mac/scripts/bundle`) signs the helpers, the frameworks and the app with the owner's Developer ID, the hardened runtime and a secure timestamp.

**Drop `get-task-allow`, as 0.1.0's was.** Xcode signs `com.apple.security.get-task-allow` into the app's entitlements, which notarization refuses, and `bundle` keeps it when it signs the app again (`--preserve-metadata=entitlements`); its fix was left for after 0.1.0, and isn't on main. Without it, step 10 can notarize this same zip. Sign the app again with its own entitlements, then check it:

```sh
cd ~/src/jaw-v0.1.1
id=$(security find-identity -v -p codesigning | awk '/"Developer ID Application:/ && index($0, "(3JP75Z3F98)\"") { print $2; exit }')
codesign --force --options runtime --timestamp --sign "$id" --entitlements mac/JawApp/Jaw.entitlements mac/build/release/Jaw.app
codesign --verify --deep --strict --verbose=2 mac/build/release/Jaw.app
codesign -d --entitlements - mac/build/release/Jaw.app
codesign -dvv mac/build/release/Jaw.app 2>&1 | grep -E '^(Authority=Developer ID Application|Timestamp=)'
plutil -extract CFBundleShortVersionString raw mac/build/release/Jaw.app/Contents/Info.plist
```

- See: "valid on disk" and "satisfies its Designated Requirement"; the entitlements Contacts (`com.apple.security.personal-information.addressbook`) and the microphone (`com.apple.security.device.audio-input`), and no `get-task-allow`; `Authority=Developer ID Application: Pedro Gomes (3JP75Z3F98)` and a `Timestamp=` line; then `0.1.1-prealpha`.
- If `codesign` can't reach Apple's timestamp server, it fails and signs nothing: try again later rather than sign without `--timestamp`, since notarizing needs the timestamp. If it waits on a keychain prompt, which nobody's here to answer, stop it: Jaw.app then waits for the owner.

**Zip it,** with `ditto`, and check what people will download, as they'll have it:

```sh
mkdir -p mac/build/zip
ditto -c -k --keepParent mac/build/release/Jaw.app mac/build/zip/Jaw-0.1.1.zip
shasum -a 256 mac/build/zip/Jaw-0.1.1.zip
ditto -x -k mac/build/zip/Jaw-0.1.1.zip mac/build/zip/unzipped
codesign --verify --deep --strict mac/build/zip/unzipped/Jaw.app && mac/build/zip/unzipped/Jaw.app/Contents/Helpers/jawd --version
spctl --assess -vv --type execute mac/build/zip/unzipped/Jaw.app
```

- See: the sha256, for step 7; the unzipped copy verifying, and `jawd 0.1.1`; then `spctl` refusing it, `rejected` with `source=Unnotarized Developer ID`. That's expected: Gatekeeper refuses an app that isn't notarized until someone opens it the way the notes say.
- Nothing here opens or installs it: it stays in the tag's worktree until step 9, and the owner's own Jaw is left as it is.
- Undo: `rm -rf ~/src/jaw-v0.1.1/mac/build/release ~/src/jaw-v0.1.1/mac/build/zip`.

## 10. Later, and optional: the owner notarizes the same zip

The owner's, in Terminal.app, which reaches Apple as Cursor's sandbox can't, with the `jaw-notary` keychain profile. The zip on the release is already what notarizing takes, every piece signed with a secure timestamp and `get-task-allow` out, so this replaces the release's file under the same name: no new release, tag or formula.

```sh
mkdir -p /tmp/jaw-v0.1.1-notarize/signed && cd /tmp/jaw-v0.1.1-notarize
gh release download v0.1.1 --repo pdcgomes/jaw --pattern Jaw-0.1.1.zip --dir signed
xcrun notarytool history --keychain-profile jaw-notary > /dev/null && echo stored
xcrun notarytool submit signed/Jaw-0.1.1.zip --keychain-profile jaw-notary --wait
```

- See: `stored`, then `status: Accepted`. With no such profile, store it first, with an app-specific password for the Apple ID: `xcrun notarytool store-credentials jaw-notary --apple-id <the Apple ID's email> --team-id 3JP75Z3F98`. If it's Invalid, `xcrun notarytool log <its id> --keychain-profile jaw-notary` says why.

Then staple it, and put it in the release's place:

```sh
ditto -x -k signed/Jaw-0.1.1.zip app
xcrun stapler staple app/Jaw.app && xcrun stapler validate app/Jaw.app
spctl --assess -vv --type execute app/Jaw.app        # accepted, source=Notarized Developer ID
ditto -c -k --keepParent app/Jaw.app Jaw-0.1.1.zip && shasum -a 256 Jaw-0.1.1.zip
gh release upload v0.1.1 Jaw-0.1.1.zip --repo pdcgomes/jaw --clobber
```

- Then the notes, on the release (`gh release edit v0.1.1 --repo pdcgomes/jaw --notes-file <the notes, edited>`) and on main: Jaw.app's paragraph says it's notarized, and loses the steps for opening it.
- Undo: `gh release upload v0.1.1 signed/Jaw-0.1.1.zip --repo pdcgomes/jaw --clobber` puts the signed zip back.
- Then `rm -rf /tmp/jaw-v0.1.1-notarize`.
