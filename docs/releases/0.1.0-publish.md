# jaw 0.1.0: publishing it

Friday 6 November: the terms and side-project check, then `pdcgomes/jaw` public, `v0.1.0` tagged and released with its source tarball, the tap `pdcgomes/homebrew-jaw` made with the formula in it, and `brew install pdcgomes/jaw/jaw` tried on a clean Mac. Each step has its commands, what to see, and what undoes it if it fails. About an hour and a half, half of it the clean Mac's install.

The tag and the tarball are made first, on this Mac alone, so a tarball that doesn't build leaves nothing public.

## Before Friday

- Thursday's spare-number session is done, and whatever it found that blocks the release is fixed on main. Its S22 ends on Friday, a day after it began, when the two disappearing messages go, and the tag (step 3) waits for that result.
- The release's documents are on main, from the release-prep branch: the release notes (`docs/releases/0.1.0.md`), Thursday's checklist and this one, the formula's fixes, `scripts/release.sh`, which step 4 runs and which refuses to go without the notes, and the README's "What it costs" with 5 November's load runs. The README's install line is `brew install pdcgomes/jaw/jaw`, as it has been on main since its pictures landed.
- The notes match main as it is then. Disappearing and view-once messages, the terminal's votes, stars and saves, jawd ending its engine however it stops, and the disk watchdog had all landed by 5 November, and the notes have them. Whatever lands after that and changes what they say, the coordinator changes in them and lands: a fix for jawd's wake-ups when idle changes that known limit, and main's CI passing on Linux again puts back, in "Where it's been run", that Linux passes jaw's tests on every change.
- `gh auth status` says you're signed in as pdcgomes, with the `repo` scope.
- About 60 GB free for the clean Mac's virtual machine: `df -h /System/Volumes/Data`.

## 1. The terms and side-project check

- Do: read WhatsApp's [Terms of Service](https://www.whatsapp.com/legal/terms-of-service) on unofficial clients and Meta's rules on side projects, as you did on 28 October, and make sure anything they ask you to ask or declare is done.
- If it doesn't hold: stop here. Nothing has been published.

## 2. main is the release

```sh
git -C ~/src/jaw fetch origin
git -C ~/src/jaw log -1 --format='%h %s' origin/main
gh run list --repo pdcgomes/jaw --branch main --limit 3
```

- See: the commit you mean to release, and CI's latest run on it passed (✓).
- If Linux's test job is green by then, the notes say so again before the tag: on main, their "Where it's been run" gets back "Intel Macs and Linux build from the same source, and Linux passes jaw's tests on every change, but neither has been tried with a real account." If that changes main, start this step again.
- If Linux's test job is still red, and nothing else is, the release goes out for macOS only, and the notes keep that line out, as they are. The run's `data-audit` and `parity` jobs must be green, and so must the macOS test job, which runs only by hand:

  ```sh
  gh run view <the run's ID> --repo pdcgomes/jaw                                     # data-audit ✓, parity ✓
  gh workflow run ci.yml --repo pdcgomes/jaw --ref main
  gh run list --repo pdcgomes/jaw --branch main --event workflow_dispatch --limit 1   # the run just started
  gh run watch <its ID> --repo pdcgomes/jaw                                          # test (macos-latest, true) ✓
  ```

  The run started by hand is listed a few seconds after it starts, and runs Linux's test job again, which may fail again.
- If anything else is red: fix it on main first, and start this step again. On 5 November main's CI hadn't passed since 16 October, and its Linux job was failing at `make lint`; the fix was being made on the branch `linux-ci`.

## 3. Tag v0.1.0, on this Mac only

First, S22's second half has passed: the two disappearing messages in Y's chat have gone from jaw and from both phones, S and Y (Thursday's checklist, S22). If their time hasn't come yet, the tag waits for it; once S22 has passed, do step 2 again, in case main moved meanwhile.

```sh
git -C ~/src/jaw tag -a v0.1.0 -m "jaw 0.1.0" origin/main
git -C ~/src/jaw worktree add --detach ~/src/jaw-v0.1.0 v0.1.0
```

The worktree is a clean checkout at the tag, which `scripts/release.sh` needs, whatever `~/src/jaw` has uncommitted.

- Undo: `git -C ~/src/jaw worktree remove ~/src/jaw-v0.1.0 && git -C ~/src/jaw tag -d v0.1.0`.

## 4. Build the release's assets

```sh
cd ~/src/jaw-v0.1.0 && scripts/release.sh
```

- See: `target/dist/jaw-0.1.0.tar.gz` and its `sha256 …`, the formula with that url and sha256, and the commands for the steps below, ending "Nothing has been pushed or published".
- Then build the tarball as Homebrew will, about four minutes, and see it say its version:

  ```sh
  mkdir -p /tmp/jaw-v0.1.0-check && tar -xzf ~/src/jaw-v0.1.0/target/dist/jaw-0.1.0.tar.gz -C /tmp/jaw-v0.1.0-check
  make -C /tmp/jaw-v0.1.0-check/jaw-0.1.0 install PREFIX=/tmp/jaw-v0.1.0-check/prefix
  /tmp/jaw-v0.1.0-check/prefix/bin/jaw --version   # jaw 0.1.0
  rm -rf /tmp/jaw-v0.1.0-check
  ```

- If it fails: nothing has left the Mac. Undo step 3, fix it on main, and start again from step 2.

## 5. Make pdcgomes/jaw public

Everything on GitHub becomes public with it: main and all its history (1,024 commits on 5 November), its docs and audits, `.cursor/` and `marketing/`, and every other branch there, so those go first. On 5 November GitHub had three besides main: `release-prep-preview`, `release-prep-preview-2` and `linux-ci`, previews of the release's documents and a fix meant for main, each on this Mac too; and the history of all four had no keys, tokens, certificates or databases, and its phone numbers were all made up. Skim `docs/audits/` and `docs/first-run.md` for anything about your own account you'd rather keep, and to look again, at every branch GitHub has:

```sh
git -C ~/src/jaw fetch origin
git -C ~/src/jaw rev-list --objects --remotes=origin | grep -iE '\.(db|sqlite3?|db-wal|p12|pem|key)$'
git -C ~/src/jaw log --remotes=origin --oneline -G'BEGIN [A-Z ]*PRIVATE KEY|gh[po]_[A-Za-z0-9]{30,}|github_pat_[A-Za-z0-9_]{20,}|xox[abprs]-[A-Za-z0-9-]{10,}|AKIA[0-9A-Z]{16}|sk-ant-[A-Za-z0-9_-]{10,}|sk-[A-Za-z0-9]{32,}|AIza[0-9A-Za-z_-]{35}'
```

Both should print nothing. They come before the branches go, since GitHub keeps a deleted branch's commits for a while, for anyone who has their hashes. Then list every branch but main, with the commit each is at, and keep the list for the undo:

```sh
git -C ~/src/jaw ls-remote --heads origin | grep -v 'refs/heads/main$'
```

Delete each it lists, by name. These are 5 November's three: leave out any it no longer lists, since a branch that isn't there makes the push fail, and add any other it does:

```sh
git -C ~/src/jaw push origin --delete release-prep-preview release-prep-preview-2 linux-ci
```

and check that nothing but main is left, and that there are no pull requests, whose commits GitHub keeps under `refs/pull/` and shows on a public repository even once their branch is deleted:

```sh
git -C ~/src/jaw ls-remote origin                       # HEAD and refs/heads/main, nothing else
gh api repos/pdcgomes/jaw/branches --jq '.[].name'      # main
gh pr list --repo pdcgomes/jaw --state all               # nothing
```

- Undo, for a branch deleted that should have stayed: `git -C ~/src/jaw push origin <commit>:refs/heads/<name>`, with the commit the list gave it.
- If a pull request is listed: its commits go public with the repository. Read what they hold before going on.

Then:

```sh
gh repo edit pdcgomes/jaw --visibility public --accept-visibility-change-consequences
gh repo view pdcgomes/jaw --json visibility --jq .visibility   # PUBLIC
gh api -X PUT repos/pdcgomes/jaw/private-vulnerability-reporting
```

The last turns on Report a vulnerability, which the release notes point security reports to.

- Undo: `gh repo edit pdcgomes/jaw --visibility private --accept-visibility-change-consequences`. Stars and watchers are lost, and forks made meanwhile stay public.

## 6. Push the tag

```sh
git -C ~/src/jaw push origin v0.1.0
git -C ~/src/jaw ls-remote --tags origin v0.1.0
```

- See: the tag, at the commit from step 2. The pre-push hook checks only pushes to main.
- Undo, only before step 7: `git -C ~/src/jaw push origin :refs/tags/v0.1.0`.

## 7. The GitHub release

Made as a draft first, so you see its notes as they'll read before anyone else does:

```sh
gh release create v0.1.0 ~/src/jaw-v0.1.0/target/dist/jaw-0.1.0.tar.gz --repo pdcgomes/jaw --verify-tag --title "jaw 0.1.0" --notes-file ~/src/jaw-v0.1.0/docs/releases/0.1.0.md --draft
gh release view v0.1.0 --repo pdcgomes/jaw --web
gh release edit v0.1.0 --repo pdcgomes/jaw --draft=false --latest
curl -sSfL https://github.com/pdcgomes/jaw/releases/download/v0.1.0/jaw-0.1.0.tar.gz | shasum -a 256
```

- See: the release page with the notes and `jaw-0.1.0.tar.gz`; once published, curl's sha256 the same as step 4's.
- Undo: `gh release delete v0.1.0 --repo pdcgomes/jaw --yes`, which keeps the tag (`--cleanup-tag` deletes it too).

## 8. The tap

```sh
gh repo create pdcgomes/homebrew-jaw --public --description "Homebrew tap for jaw"
git clone https://github.com/pdcgomes/homebrew-jaw ~/src/homebrew-jaw
git -C ~/src/homebrew-jaw branch --show-current   # main
```

Git warns that it cloned an empty repository, which is expected. If the branch isn't `main`, `git -C ~/src/homebrew-jaw checkout -b main` makes it so.

- Undo: `gh auth refresh -h github.com -s delete_repo`, since deleting a repository needs that scope, then `gh repo delete pdcgomes/homebrew-jaw --yes` and `rm -rf ~/src/homebrew-jaw`.

## 9. The formula, into the tap

```sh
mkdir -p ~/src/homebrew-jaw/Formula
cp ~/src/jaw-v0.1.0/target/dist/jaw.rb ~/src/homebrew-jaw/Formula/jaw.rb
grep -E '^  (url|sha256) ' ~/src/homebrew-jaw/Formula/jaw.rb
git -C ~/src/homebrew-jaw add Formula/jaw.rb
git -C ~/src/homebrew-jaw commit -m "jaw 0.1.0"
git -C ~/src/homebrew-jaw push origin HEAD
```

- See: `url "https://github.com/pdcgomes/jaw/releases/download/v0.1.0/jaw-0.1.0.tar.gz"` and step 4's sha256, then the push.
- Undo: `git -C ~/src/homebrew-jaw revert --no-edit HEAD && git -C ~/src/homebrew-jaw push origin HEAD`, which takes jaw out of the tap again.

## 10. brew install on a clean Mac

A macOS virtual machine with Homebrew and nothing else, through tart (`~/.local/bin/tart`), from your own terminal rather than Cursor's:

```sh
tart clone ghcr.io/cirruslabs/macos-tahoe-base:latest jaw-clean
tart run jaw-clean
```

If tart can't find that image, the newest macOS base image of [cirruslabs' list](https://github.com/cirruslabs/macos-image-templates) does as well. In the machine's Terminal (user and password `admin`):

```sh
time brew install pdcgomes/jaw/jaw
jaw --version && jawd --version
"$(brew --prefix)/opt/jaw/libexec/jaw/jaw-engine" --version
brew test pdcgomes/jaw/jaw
brew audit --strict --online pdcgomes/jaw/jaw
jaw demo
```

- See: Homebrew installs Go, Rust, cmake and ffmpeg, then builds jaw from the tarball and ends with jaw's caveats; `jaw 0.1.0`, `jawd 0.1.0` and `jaw-engine 0.1.0 (whatsmeow …)`; the test and the audit passing; and `jaw demo` drawing the made-up account (Ctrl-C quits). Write down how long the install took. Don't link an account in the machine.
- If the install fails on the formula: fix it in `~/src/homebrew-jaw` (and in `packaging/homebrew/jaw.rb` on main), push, then `brew update` in the machine and install again. If it fails on the tarball itself, undo steps 7, 6 and 9 and the tag, fix it on main, and start again from step 2 with the same version, since nobody has installed it yet.
- Then: `tart delete jaw-clean`, and `tart prune --entries=caches --older-than=0` for the image it downloaded, tens of GB (and anything else tart had cached).

## 11. Afterwards

- `git -C ~/src/jaw worktree remove ~/src/jaw-v0.1.0`. Keep `~/src/homebrew-jaw` for the next release's formula.
- If your own jaw moves to Homebrew's, `make uninstall PREFIX=~/.local` first (from `~/src/jaw`), so one jaw is on your PATH. Both use the same folder and the same chats.
- Tell the coordinator: the board's "Publishing the first release" is done.
