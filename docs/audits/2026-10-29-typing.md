### Bounded memory

What typing keeps, and what bounds it:
- **The intake** (`feed/typing.rs:71-80`, `:141-176`) holds at most 1,024 of the engine's typing and of the messages that end it, checked before each push; each entry is two or three JIDs, so under 200 KB.
- **Each chat's typists** (`Typists::chats`) are kept while someone types there, a change is owed, or for one pace after it was last told (`:454-456`); a chat's typists are at most its members.
- **The chats and people read** (`chat_ids`, `people`) are let go of once a second, down to those of chats someone types in and people typing (`forget`, `:459-471`), so between two prunes they hold at most what one second of typing named.
- **What connections are told** (`told`) holds the chats someone types in.
- **The rounds told** go to connections through a broadcast of 1,024 rounds (`CHANGES_KEPT`). tokio drops a round once every receiver has taken it, so only a connection that falls behind keeps rounds alive, at most 1,024. A round lists the chats told in it, each chat at most once a pace (50 ms), and rounds come at most every 5 ms, so 1,024 rounds hold at most about 100 ids per chat whose typing keeps changing: 0.3 MB for 50 such chats, 2 MB for 300. Past that the connection is told it lagged and looks again at every chat it shows. A connection's task takes rounds whether or not its interface reads (`client.rs:1083`), so only a connection whose own task stalls, in a window read, falls behind.
- **Each connection** keeps who its interface holds as typing and the chats owed a push (`typists`, `typing_owed`), both for the chats its windows show only, so at most 32 windows' chats; a connection whose interface reads nothing holds one push owed for each, and after `behind` (5 s) is told to watch again, which forgets them (`client.rs:1112-1117`).
- **The task's work** is a round at most every 5 ms while typing comes, each looking at the chats with typing, and none while nobody types: with nobody typing it waits on nothing but the intake and `hearing`, so idle stays idle.

One structure is bounded by the account's chats rather than by a number: **what messages are looked for in** (`Intake::watching`). `heard` adds every chat it hears to it, and it's set back to the chats with typists only in a round where someone started or stopped (`:547-563`). Typing that places nobody leaves its chats there: your own devices' typing, typing from people jaw has no person for, in chats it doesn't have, or said while you're away. My probe had your own devices type in 500 chats: all 500 stayed in `watching` until someone jaw shows started typing, when it went back to one, and meanwhile a message in any of them took a place in the intake and a round of the task (O3).

### Coalescing, drops and `jawd status`

Each chat's typing is told at most once a pace, the first change after a quiet spell at once (`tell`, `:424-456`), and the pace is kept across a chat that empties: a chat stays in `Typists::chats` for a pace after it was last told, so typing that starts again there waits for it. The pace test pins the first and the merging, but only for a chat someone types in throughout; with the chat let go of as soon as it empties, no test fails (T3). Typing dropped for a full intake is counted in `dropped` and reported in `jawd status`'s `typing` with `heard`, `waiting`, `waiting_most`, `sent`, `merged` and `chats`, and the end-to-end test and jaw-client's `describe` test read it. A message dropped for a full intake ends everyone's typing in the round that takes what was held, after it, which is the right order: nothing more is taken while the intake is full, so what it held is exactly what came before the message. That message isn't counted anywhere, though (O2).

### The feed

- **Each watch's answer and the pushes agree.** An answer's `typing` covers every chat of the window, rows left out as unchanged included (`typing_in`, `client.rs:799-815`), and takes those chats out of what's owed. A change told afterwards is owed and sent only if it differs from what the interface was told (`flush_typing`, `:825-849`), so a round told just before the answer and taken just after it sends nothing twice.
- **Watching again from `since` gives what a fresh watch gives.** Typing in an answer doesn't depend on `since` or `have`, and the builder's test checks both a chat list and a conversation against a fresh connection.
- **Pushes go in order with the windows'.** They share the connection's one queue, and `shows` reads what the interface was last sent, so a typing push for a chat is queued after the window push that brings it in (owed as it comes, `:1253-1258`), and one queued before the push that takes a chat out is for a chat the interface still holds. With the queue full, typing waits with the window updates, one push owed for each chat, and the connection counts as blocked, so `behind` still applies.
- **A chat that leaves every window and comes back** is forgotten as it leaves by a window's push (`left`, `:1250-1252`), and told again once it's back. It's also forgotten when its window is unwatched (`:896`) and when the connection is told to watch everything again (`:1115`). Those two are right, but no test fails without either (T2).
- **No spin.** With typing owed and the queue full, or a reply waiting for room, `flush` marks the connection blocked and `ready` then waits for room or for `behind`, as for windows.

### Ending typing

- **A message from them in that chat** is taken from sync's Message arm for every message not from you, before its inbox write (`sync/mod.rs:363-365`), with its chat, sender and `sender_alt`. Where nobody types it costs a lock and a check; elsewhere a look in `watching`. `messaged` ends the typists the message's JIDs name, or whose person they name, in that chat only (`:399-408`). Tested at `Typing::message` for a group, for her LID's chat, and for a LID jaw doesn't know with the number beside it. Through sync, though, no test sends a message with a `sender_alt`: with sync passing none, every test passes (T1).
- **The builder's edge is real, and cheap to close.** A message in a one-to-one chat by the JID typing didn't come by, arriving before the task's next round has set `watching` from who's typing, isn't taken: `message` looks only for the message's chat (`:164-167`), and typing by number put only her number there. My probe, Ana typing by number in her chat and her message by her LID coming at once with her number beside it, left her shown typing until she would fade 25 s later. That's at the API, and through sync's loop with folders' `Typing` event (below). The window is the round's wait (up to 5 ms) and its read of names, longer under load. In a one-to-one chat the message's `sender_alt` is the chat's other JID, so looking for it too closes the edge. I switched that on (`fix_alt`: in `message`, a person chat not looked for is taken if its `sender_alt` is; in `messaged`, a person chat not found is looked for by the `sender_alt`): her typing was ended in the round that took both, so it was never shown, and the 17 typing tests still pass (O1).
- **A pause** ends only theirs, whichever JID it names them by, at once.
- **Going away and WhatsApp unreachable.** `hearing` is `online && told == Some(true)` (`send/presence.rs:35-36`), recomputed each time round the presence loop: it goes false once WhatsApp has been told you're away, or as soon as a `connection` push says it can't be reached (connection lost, the engine restarting), and true only once you've been told online again after the connection came back. The typing task ends everyone's typing in any round where `hearing` is false or its sender has gone, and drops what it takes then. Tested on both sides. What comes while away is also taken and ended in the same round with that drop switched off (`away_taken`), so that switch changes nothing anyone sees: equivalent.

### The seam with folders

On `folders` (`53981ad`), the engine forwards whatsmeow's `*events.ChatPresence` as the link's `Typing` event (`engine/internal/wa/engine.go:196-197`, `presence.go:30-39`), sent with `e.send`, without an ack, from whatsmeow's one event queue, the same queue whose messages wait for their acks with `keep`. So a chat presence and the messages around it reach jawd's one `incoming` channel and sync's loop in the order whatsmeow dispatched them, and nothing about typing is acknowledged or stored. jawd's arm on `folders` is empty (`crates/jawd/src/sync/mod.rs:250`).

I tried the arm the builder proposes, `Some(pb::event::Kind::Typing(t)) => typing.heard(&t.chat, &t.sender, t.state())`, in the scratch clone: folders' `Typing` message and field 16 added to `engine.proto` (nothing else of folders), the arm in `sync::run` (it's needed: the match has no wildcard), and the demo engine's typing sent as `Typing` events through its link when `JAW_TYPING_LINK` is set, as the Go engine will send them, rather than handed to `Typing::heard`. With it:
- a test through sync's loop passes: typing by LID with a device in a group and by number in her chat is heard, her message in the group by number ends hers there and nowhere else, and a pause ends hers in her chat;
- the end-to-end `crates/jaw/tests/typing.rs` passes with the demo's typing through the link, on a jawd rebuilt with the arm (63 s);
- the builder's edge happens through the loop as at the API (her typing still shown after her LID's message).

So the arm is right: `heard` never waits, takes no lock sync holds, and `t.state()` reads an unknown state as unspecified, which is a pause. It isn't complete: whatsmeow's `parseMessageSource` fills `SenderAlt` from `participant_pn`, `participant_lid`, `sender_pn` or `sender_lid` for chat states as for messages, and `IsFromMe` from both your JIDs, and `typing()` forwards neither. Without the other JID, typing by a JID jaw has no person for isn't shown even when WhatsApp says who it is (O4). `Me` includes your LID (`sync/mod.rs:388`), so your own devices are left out without `IsFromMe`. Folders' sync test `typing_and_recording_heard_from_whatsapp_write_nothing_to_jaw_db` needs `run`'s new argument, as the builder says.

### Switches

Besides the builder's 50, I built 43 switches of my own into one debug build, each turned on by `JAW_MUT`, with a baseline of the 17 typing tests passing with none on, and ran the 17 tests under each. 35 fail at least one test, each at the rule switched off. Eight pass:
- `away_taken` (what's said while away taken): equivalent, as above.
- `sync_no_alt` (sync passing no `sender_alt` to `Typing::message`): T1.
- `unwatch_no_forget` and `behind_no_forget` (a connection not forgetting the typing of chats its unwatched window, or its windows dropped for falling behind, showed): T2. Without either, a chat that later comes back into a window with its typing unchanged isn't told, and its interface shows nobody typing there.
- `retain_no_pace` (a chat let go of as soon as it empties, losing when it was last told): T3. A chat whose typing stops and starts again is then told again at once each time it has emptied, twice a pace in my test.
- `tell_unchanged` (a chat that changed and changed back told anyway): connections send nothing for it, so it costs a round of the broadcast and leaves the next change waiting a pace; a cost, not a rule.
- `batch_off` (no 5 ms between rounds) and `forget_never` (what's read never let go of): costs, which the builder measured rather than tested. `forget_never` failed `typing_writes_nothing_to_jaw_db_and_moves_no_seq_while_interfaces_are_told_it` twice in four runs; that's the test's race (O5), since the unswitched test passed four of four meanwhile and keeping what's read changes nothing anyone is told.

The switches, the probes and the seam are in this auditor's store (below).

### The ack, and what's written under a flood

I checked the builder's method: eight interleaved pairs of `jawd demo --flood 2000 --seconds 30 --in-flight 256 --after 3` with `--typing 50` and without, a release jawd at the head, on one million-message account. It's sound for what it measures, but the demo's typing went straight to `Typing::heard` from a task of its own, so it measured typing's task and the connections and not the seam: the link, the shared `incoming` channel and sync's loop, where the Go engine's typing will arrive. So I repeated it with four arms, the seam among them, all on one release build of the head with the seam patch (its no-typing and direct arms run exactly the head's code): no typing; typing in 50 chats told directly (the builder's arm); the same 50 chats through the link and sync's loop; and 300 chats through the link (all `TYPING_AMONG`, about 2,000 changes a second). Eight rounds, the arms' order rotating each round, each run on its own APFS clone (`cp -c`) of one made-up account of 1,000,860 messages in 3,000 chats, fully indexed, under `nice`, at a load of 57 to 78 on 20 cores. Typing adds nothing measurable to a message's ack or to its way to the interface, through the seam or not, at 50 chats or 300 (numbers under Measurements). Every run wrote exactly 60,000 `message` events, its `chat` events fell between 47,048 and 47,125 in every arm alike, and nothing else was written. In a typing-only phase, 300 chats typing through the link for 20 s while 4,910 pushes went to the demo's interface, jaw.db's last seq moved exactly as in the same 20 s with nobody typing (by 50, the demo's start), so typing wrote nothing there either.

## Findings

### Data loss

None. Typing is never written, by structure (read-only connections, no call to the writer), by the builder's test, and measured under floods and alone.

### Inconsistency

None in jaw.db or between the feed and the tables: typing moves no `v` and no `seq`, and windows' rows are what they were. What an interface holds of typing can disagree with jawd's in one race (O7); that's typing in memory, never stored, and I've put it under Other.

### Tests (missing)

None of these blocks: each rule below has a test that fails without it, and what's untested is a path that decides what an interface shows of typing, which jaw.db never keeps, as with the layout book's T1. Each test printed under "The tests to adopt" passes at the head 3 of 3 and fails 3 of 3 with its rule switched off; they're cheap to land with the trailers.
- **T1, test gap. Sync's handing on of a message's other JID is untested.** `sync/mod.rs:364` passes `info.sender_alt` to `Typing::message`; with it passing none, every test passes (`sync_no_alt`), since sync's typing test sends no message with a `sender_alt`. A message by a LID jaw doesn't know someone by, with the number they typed by beside it, would then leave them typing. **Fix:** adopt `a_message_by_a_lid_jaw_doesnt_know_with_the_number_beside_it_ends_their_typing_through_sync`, which fails with the switch ("her typing's end by a LID jaw doesn't know her by never came").
- **T2, test gap. A connection forgetting the typing of chats its windows no longer show is tested on one of its paths.** It's tested where a window's push takes a chat out (`left`), not where the window is unwatched (`client.rs:896`) or the connection is told to watch again for falling behind (`:1115`). The two other paths, a `watch.move` (`:1061`) and a window whose reads keep failing (`:1228`), I didn't switch. Without either forget, a chat that comes back into a window with its typing unchanged isn't told, and its interface shows nobody typing there until it changes. **Fix:** adopt `a_chat_whose_conversation_is_unwatched_is_forgotten_and_told_again_once_it_comes_into_a_chat_list` and `a_connection_told_to_watch_again_forgets_whos_typing_and_tells_a_chat_once_it_comes_back`, which fail with `unwatch_no_forget` and `behind_no_forget` ("its interface was never told …").
- **T3, test gap. The pace is untested across a chat that empties.** The pace test keeps someone typing in its chat throughout. With a chat let go of as soon as it empties, so that its last tell is forgotten, every test passes (`retain_no_pace`), and a chat whose typist stops and starts again is told twice a pace. **Fix:** adopt `a_chat_whose_typing_stops_and_starts_again_is_still_told_at_most_once_a_pace`, which fails with the switch ("11 changes told in 2.67 s, at most 7 at one a 500ms").

### Unpredictable performance

None that breaks a budget. Typing adds nothing measurable to the ack or the push. The one cost on sync's loop is a lock, below as O8.

### Other (follow-ups; none blocks)

- **O1, other. A message in a one-to-one chat by the JID typing didn't come by, within a round of the typing, doesn't end it** (the builder's edge). `Typing::message` looks only for the message's chat in `watching` (`feed/typing.rs:164-167`), which holds only the chat's JID as typing named it until the task's next round has set it from who's typing, which takes up to 5 ms plus a read of names, longer under load. Shown at the API and through sync's loop: her typing stays until she pauses, says something else, or fades 25 s later. **Fix:** in a person chat, also look for the message's `sender_alt`, which there is the chat's other JID, in `message`, and in `messaged` find the chat by it when the chat isn't found. With that switched on (`fix_alt`) the edge closes, and the 17 typing tests pass. The test for it, printed with the others below, fails 3 of 3 at the head (she's left shown typing) and passes 3 of 3 with the fix, so it lands with the fix.
- **O2, other. A message dropped for a full intake isn't counted.** `message` sets `lost` and returns (`:168-171`), counting nothing, so the round in which everyone's typing ends for it doesn't show in `jawd status`, while the design says what comes while the intake is full is dropped and counted. **Fix:** count it, in `dropped` or a counter of its own. Rounds a connection fell behind by aren't counted either.
- **O3, other. What messages are looked for in keeps chats nobody shown types in.** Above, under Bounded memory: `Intake::watching` is bounded by the account's chats, not by a number, and while it holds chats nobody types in, each message in them costs an intake slot and a round. **Fix:** set it from what's waiting and who's typing in every round that took typing, not only when someone started or stopped.
- **O4, other. The seam carries no `sender_alt`.** whatsmeow gives chat states the other JID as it does messages, and folders' `typing()` forwards only `Sender.ToNonAD()`. **Fix:** add `string sender_alt = 4` to the link's `Typing`, fill it from `v.SenderAlt.ToNonAD()`, and have `heard` read a typist by either JID, as `messaged` does.
- **O5, other. The builder's nothing-written test races its interface.** `typing_writes_nothing_to_jaw_db_and_moves_no_seq_while_interfaces_are_told_it` (`feed/tests.rs:4131`) gives its interface a fixed 300 ms to watch, then counts at least four typing pushes. If the watches answer late, the answers say what the first pushes would have, and it sees three. It failed so twice in four runs under a switch that changes nothing anyone is told (`forget_never`), and passed four of four and then six of six run at once without it. **Fix:** start typing once both answers are in.
- **O6, other, for the landing. The Mac app speaks protocol 1.** This branch raises `PROTOCOL` to 2, as the protocol's Versioning asks for a field going, and jawd refuses any other with error 6 (`sock.rs:600-622`). JawKit still says `protocolVersion = 1` (`mac/JawKit/Sources/Protocol/Envelope.swift:4`), so once this lands Jaw.app can't connect to jawd. JawKit already reads chat rows without `typing` (`Rows.swift:55`), so bumping its version, and its FakeJawd's answer, is all it needs. It should land with this branch, and the Mac branches in flight need it as they rebase.
- **O7, other. An interface that forgets as it unwatches can miss a chat's typing.** jaw-client forgets a closed window's chats' typing as it sends `unwatch` (`jaw-client/src/client.rs:563-569`). A push jawd sent before reading the `unwatch` can bring one of those chats into a chat list, and jawd doesn't tell its typing, since by its reckoning the interface still holds it: `flush_one` owes a chat that comes in only if `typists` lacks it (`feed/client.rs:1253-1259`). The interface then shows nobody typing there until the typing changes. My probe, which forgets in jaw-client's order with the chat pinned into the list before jawd reads the `unwatch`, fails 3 of 3 at the head. **Fix:** tell a chat that comes into a window with someone typing whether or not the interface held it, as the protocol says ("just after the window's push that brings a chat in with someone typing"). With that switched on (`fix_came`), the probe passes 3 of 3 and the 21 typing tests pass. It costs a push now and then for a chat another window already shows.
- **O8, other. The intake's lock is held while `watching` is set again.** The task builds the new set from who's typing and what's waiting while holding the lock (`feed/typing.rs:551-563`), which sync's loop takes for every message and every typing event. In a debug build at load 60 to 70, `heard` and `message` cost their caller 4.8 µs at p50 and 20 µs at p99 with the task running, as without it (4.6 and 18 µs), but 183 µs at p999 against 56 µs. **Fix:** build the set outside the lock and swap it in.
- **O9, other. A chat or person merged while someone types keeps their typing under the old id** until they've stopped for a second, since what's read is kept while they type (`chat_ids`, `people`). Rare and brief; nothing is stored.

    #[tokio::test(flavor = "multi_thread")]
    async fn a_chat_whose_typing_stops_and_starts_again_is_still_told_at_most_once_a_pace() {
        let pace = ms(500);
        let mut bed = Bed::new(Timing { fade: LONG, pace }).await;
        // Rui types and stops every 20 ms for 3 s, so nobody types there between his changes.
        let typing = bed.typing.clone();
        let burst = tokio::spawn(async move {
            let began = Instant::now();
            let mut n = 0u64;
            while began.elapsed() < ms(3_000) {
                typing.heard(GROUP, RUI, if n.is_multiple_of(2) { Composing } else { Paused });
                n += 1;
                tokio::time::sleep(ms(20)).await;
            }
            began
        });
        let (mut tells, mut last) = (0u64, Instant::now());
        loop {
            match tokio::time::timeout(pace * 3 / 2, bed.seen.changed()).await {
                Ok(Ok(chats)) if chats.iter().all(|chat| &**chat == GROUP) => {
                    (tells, last) = (tells + 1, Instant::now())
                }
                Ok(other) => panic!("{other:?}"),
                Err(_) if burst.is_finished() => break,
                Err(_) => {}
            }
        }
        let began = burst.await.unwrap();
        let lasted = last.saturating_duration_since(began);
        let most = (lasted.as_millis() / pace.as_millis()) as u64 + 2;
        assert!(tells <= most, "{tells} changes told in {lasted:?}, at most {most} at one a {pace:?}");
    }
