# Audit: the move from make to mise

Range: fdeba680..cab9fb35 in `mise` (`~/src/jaw-mise`), 7 November 2026, round one. Auditor: database-expert. GitHub's main has since moved to a1a7659f, one docs-only commit; "Landing" says what that changes.

## The change

Twenty-five commits replace the Makefile with mise tasks: a root `mise.toml` and a bash file per task in `mise/tasks/`, with CI, the Homebrew formula, the Mac's scripts, documents and rules following (`docs/plans/2026-11-06-jaw-mise-design.md` and its plan).

- **The data layer's part**, by `scripts/check-data-audit.py`'s paths, is one commit, 142718d7 (+16 −16 in 8 files), meant to change words only. These are the messages and comments that named make's targets:
  - jawd's `engine/go.rs` (8 lines): `find`'s comment, the handshake's two errors, and a test helper's comments, assertion message and skip note.
  - `main.rs` (2): the error for an engine it can't find, and `engine_program`'s comment.
  - `sock.rs` (1): the version error now ends "so install jaw again with mise run install".
  - `store/write/outbox.rs` (1 comment).
  - The engine's `cmd/jaw-engine/main.go` (1 comment), and `proto/engine/engine.proto` (1 comment) with the header of the Go generated from it.
  - `protocol/fixtures/error.version.json`: the same message.
- **Outside those paths, but guarding jaw.db:** `mac/scripts/built-from`, which decides whether a Jaw starts jawd on an account's folder, counts mise's tasks and settings where it counted the makefiles (5f623517, a8674649, 2e6a516f, with `test-built-from`'s cases in c33a7ffa). `mac/scripts/bundle` builds the engine with `mise/tasks/engine` where it ran `make -s engine`.

No SQL, write, transaction, acknowledgement, kept file, schema, migration, PRAGMA or fixture database changes anywhere in the range.

## Why it holds

**142718d7 changes words alone.** This was measured, not just read:

- **Rust:** each of the four files, at the commit and at its parent, was compared with its comments dropped and every string literal cut down to its format placeholders (`{}`, `{PROTOCOL}`, `{older}`). They're the same code to the character, and so are all eleven Rust files the whole range touches. The comparison does catch a dropped placeholder and a changed comparison, planted as mutants.
- **Go:** the engine built from the commit and from its parent, with the same flags, differs only in:
  - its build ID, which hashes the source text, comments included;
  - the Mach-O UUID derived from that ID (16 bytes);
  - 64 bytes of the ad hoc signature's page hashes.

  Every byte of code and data is the same, and builds from fdeba680 and cab9fb35 reproduce the two binaries exactly.
- **The proto:** `engine.pb.go` changes in its header comment alone, so its raw descriptor is the same. `mise/tasks/check-generated` at HEAD generates it again from `engine.proto` with nothing different. The Rust that `wa-proto` generates from `engine.proto` doesn't contain the file's header comment at all.
- **Swift:** the Mac's changes (`Build.swift`, `Starter.swift` and their tests) are inside string literals and comments, so `Starter`'s choice of whether to start jawd on an account's folder is unchanged.

So nothing that writes, acknowledges or reads data changed. Durability, consistency, the schema, migrations and plans are main's, and there's no plan to pin and no migration to time.

**Every test that touches the changed lines still holds**, at HEAD in the audit's clone:

- `sock::tests::hello_comes_first_and_must_match` checks the version error's code, its data and "jawd is older", which the new words keep.
- jaw-proto's `every_fixture_reads_and_writes_back_the_same` round-trips `error.version.json` through its type. Nothing compares its message with what jawd sends. The Mac's `FixtureTests` decode every fixture into JawKit's types and check no error's words; this audit read them rather than ran them, and `mise run mac-test` runs them in the gate.
- All 19 of `engine::go`'s tests ran against the engine built at HEAD, with none skipped. `the_go_engine_says_hello_answers_and_benches` goes through the handshake whose two errors changed.
- `tests/installed.rs` and jaw-proto's `jawd_linked_into_a_shared_bin_finds_the_engine_beside_its_real_folder_as_homebrew_lays_them_out` pass. They test the layout that the changed comments describe.
- No test quotes `main.rs`'s message or the outbox's comment. The line that comment says `mise run perf` reads is unchanged.

**The data layer's gate runs as make ran it.**

- `mise run test` builds the engine, then runs `go test -race ./...` in `engine/` and then `cargo test --workspace`, as `make test` did. `lint` and `check-generated` run main's commands too.
- `mise run check-audit` runs `scripts/check-data-audit.py origin/main HEAD`. `mise run setup` installs the unchanged `scripts/pre-push` into the hooks folder every worktree shares, as `make hooks` did. CI's `data-audit` job is unchanged.
- `uninstall` takes out only `jaw`, `jawd` and `jaw-engine`, and `libexec/jaw/` if it's left empty. No task touches jaw's folder.
- `mise.toml`'s `[env]` adds three signing names to every task's environment, which nothing in `crates/`, `engine/` or the scripts reads.

**built-from can't say `main` where main's said `changed` or `branch`**, except for the makefiles, which nothing builds from now.

- Its decision is main's line for line, in the same order: changes, then files git is told to ignore, then files written since, then origin, then origin/main's history, then a tag. Only what counts as an input grew.
- Every new piece widens what counts:
  - `:(icase)` on each input;
  - the settings patterns in `git status`, in `ls-files --others` and in `ls-files -v`;
  - the since-check's second loop;
  - `set -f`, and git's pathspec variables unset.
- The one input it drops is the makefiles. No task, script or build script in the workspace runs make.
- What mise reads was checked with mise 2026.9.7, in a scratch project:
  - The two task folders built-from doesn't count, `mise-tasks/` and `.mise-tasks/` at the top, can't stand in for `mise/tasks/mac`. With a `mac` task in either beside it, `mise run mac` runs `mise/tasks/mac`, from the top and from `mac/`.
  - Every miserc name in mise's binary (`miserc.toml`, `.miserc.toml`) is already matched by `*mise*.toml` or by `.config/`.
  - Idiomatic version files are off (`[]`), and there's no global config.
- `bundle` still sets `CARGO_TARGET_DIR` and `GOWORK=off` itself, so a setting can't bring another checkout's binaries in.
- No checkout on this Mac (the owner's and 21 worktrees) has a local mise settings file, so landing turns no Jaw built from main into `changed`.
- It still doesn't walk `target/`: with 100,000 more files there, it takes 0.21 to 0.24 s, against main's 0.18 to 0.20 s.

## Findings

None is data loss or inconsistency, and none must be fixed before landing.

**F1. No case pins that a tracked mise settings file hidden from git status says changed. Test gap, in the check that keeps a branch's jawd off jaw.db. The code is right. Worth adding before landing, but it doesn't block.** `mac/scripts/built-from:75`, `mac/scripts/test-built-from`.

- Take `$settings` out of the `ls-files -v` line, and `test-built-from` still passes 106 of 106.
- Yet that mutant reads `main` for a checkout at origin/main whose `mise.toml` is changed and marked assume-unchanged or skip-worktree. In the probe, the change put `RUSTFLAGS` and `CARGO_TARGET_DIR` in `[env]`. HEAD's built-from says `changed`, "with files jawd is built from whose changes git is told to ignore".
- The two cases of hidden changes there are of `crates/lib.rs` and `.MISE/config.toml`, which the inputs match, not the settings patterns.
- Hiding an edit to a committed settings file that way is a usual trick for keeping a machine's own values.
- The fix is these two cases, before `copy skipped`. With them it passes 108 of 108, and the mutant fails both:

  ```sh
  copy assumed-setting
  echo '[env]' >> mise.toml
  git update-index --assume-unchanged mise.toml
  says "mise.toml changed, which git is told to assume unchanged" changed \
      "main at $at, with files jawd is built from whose changes git is told to ignore"
  copy skipped-setting
  echo '[env]' >> mise.toml
  git update-index --skip-worktree mise.toml
  says "mise.toml changed, which git is told to skip" changed \
      "main at $at, with files jawd is built from whose changes git is told to ignore"
  ```

**F2. `go.rs`'s comment says `mise run install` puts jaw-engine beside jawd. Hygiene: a word in the data layer.** `crates/jawd/src/engine/go.rs:109`.

- `mise/tasks/install` puts it in `libexec/jaw/`, as `main.rs:516-518` says.
- `GoEngine::find` looks beside jawd (Jaw.app's layout), then in `../engine/` (a checkout's), then on PATH.
- Main's "as `make install` puts it" was just as wrong. The progress ledger's fix-round item for it didn't land.
- The fix is "beside jawd, as in Jaw.app's Contents/Helpers/". If it goes into 142718d7 before landing, as that comment's words alone, this note covers it. Otherwise it's a follow-up.

**F3. `docs/audits/README.md` still says `make check-audit`. Hygiene.** It's this folder's README, which tells you what to run, rather than a record. After landing, the command doesn't exist. The fix is `mise run check-audit`.
